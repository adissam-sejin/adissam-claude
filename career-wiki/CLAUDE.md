# 아는디자이너 커리어 LLM 위키 — 운영 규칙

김세진(아는디자이너)의 커리어·포트폴리오를 **Claude가 직접 정리하고 계속 키워 가는 마크다운 위키**.
사람은 자료를 던져 넣고 질문한다. 정리·연결·갱신은 Claude가 한다.
강의·제안·지원을 할 때마다 카드가 쌓여서 **다음 제안서가 점점 쉬워지는 것**이 목표다.

## 구조

```
career-wiki/
├─ CLAUDE.md            이 파일 (운영 규칙)
├─ inbox/               ① 수집함·원본 — 파일, 캡처, 메모, SNS 글, 후기를 그냥 던져 넣는 곳 (Claude는 읽기만, 고치지 않음)
├─ wiki/
│  ├─ index.md          전체 목차 + 한 줄 요약 (질문에 답할 때 여기부터 읽는다)
│  ├─ overview.md       한 장 요약 — 강사 소개 문단, 핵심 숫자, 강점
│  ├─ log.md            작업 기록 (추가만)
│  ├─ gaps.md           비어 있는 정보·확인할 것
│  ├─ profile/          정체성·브랜드·자격증·경력 타임라인
│  ├─ cards/            ② 경험 카드 — 경험 하나당 한 장. 한 일 / 결과 / 증거
│  ├─ competencies/     ③ 역량 페이지 — 역량별로 경험 카드를 묶어 둠
│  ├─ orgs/             ④ 기관 페이지 — 제안·지원하는 기관의 문제 정의, 톤, 결과
│  ├─ works/            ⑤ 작업물 — 제안서, 지원서, 계획서, 상세페이지 시안 기록
│  └─ queries/          다시 쓸 만한 질문과 답
├─ sites/               ⑥ 맞춤 웹 — portfolio/(전체 포트폴리오 사이트) + 기관별 제출용 페이지
└─ scripts/build_site.py  위키 → 포트폴리오 사이트 생성기
```

## 각 층의 형식

### ② 경험 카드 `wiki/cards/YYYY-기관-주제.md`
```markdown
---
type: card
period: 2025 ~ 현재
org: 데이원컴퍼니
audience: 기업 임직원
competencies: [ai-literacy, hands-on-ai]
sources: [inbox/파일, 또는 기존 스킬 data.json(2026-10)]
updated: YYYY-MM-DD
---
# 제목 (한 줄로 무슨 경험인지)

## 한 일
## 결과        ← 숫자 우선: 회차, 수강 인원, 만족도, 재계약, 결과물(전시·출간)
## 증거        ← 사진·후기·공문·링크·inbox 파일 경로
## 제안서에 쓸 한 줄
## 관련
```
- 모르는 값은 지어내지 않는다 → `(확인 필요)` + `gaps.md`에 올린다
- **결과와 증거가 카드의 힘이다.** 새 자료가 들어오면 이 두 칸부터 채운다

### ③ 역량 페이지 `wiki/competencies/이름.md`
역량 정의 한 줄 → 그 역량을 증명하는 카드 목록(가장 센 것부터) → 제안서용 요약 문단.

### ④ 기관 페이지 `wiki/orgs/기관명.md` (`_template.md` 복사)
기관 소개 / **기관의 문제 정의**(왜 이 강의가 필요한가) / 담당자·기관 **톤** / 앞세울 카드·역량 / 제출물 링크 / **결과**(선정·탈락·재계약과 이유, 다음에 고칠 점).

### ⑤ 작업물 `wiki/works/`
만든 제안서·지원서·시안 기록: 날짜, 대상 기관, 파일 위치, 결과. 좋은 문단은 다음에 재사용할 수 있게 발췌해 둔다.

### ⑥ 포트폴리오 사이트 `sites/portfolio/`
위키를 고친 뒤 `python3 career-wiki/scripts/build_site.py`로 다시 만들고, 같은 파일 경로로 Artifact를 다시 게시한다(주소 유지: https://claude.ai/artifact/WPmFuaQstCBwXiMNtokj8E). `(확인 필요)` 내용은 사이트에 나가지 않는다.
공개 주소는 Netlify **https://adidesigner.netlify.app** (site id `91cd2bf1-a82b-46e4-806d-2628cbeb5e1c`). 빌드하면 `sites/portfolio-netlify/`가 생기고, 이 폴더에서 Netlify MCP `deploy-site`가 알려주는 명령을 실행해 배포한다.

### ⑥ 맞춤 웹 `sites/기관명.html`
기관 페이지를 바탕으로 그 기관에 맞는 카드만 골라 만든 한 장짜리 소개 페이지. 브랜드 톤(웜다크 #2B2A2A · 크림 #F4F1EA · 와인 #8C0001, Freesentation)을 따른다. 필요하면 Artifact로 게시해 링크로 보낸다.

## 작업

### 넣기 — "이거 위키에 넣어줘", inbox/에 새 파일
1. 자료를 읽고 새로 알게 된 것을 3~5줄로 말한다
2. 경험 카드를 만들거나 고친다 → 역량 페이지에 연결 → 필요하면 기관 페이지·overview·타임라인 갱신
3. 기존 내용과 부딪히면 덮어쓰지 말고 둘 다 적고 `gaps.md`에 올린다
4. `index.md` 갱신, `log.md`에 `## YYYY-MM-DD 넣기 | 제목` 추가
5. 포트폴리오 사이트를 다시 만들고 다시 게시한다

### 지원·제안 — "○○기관에 제안하려고"
1. `orgs/_template.md`로 기관 페이지를 만든다(기관 조사 → 문제 정의 → 톤)
2. 문제에 맞는 역량·카드를 골라 제안서(`adi-lecture-proposal`)·지원서(`adi-instructor-application`)를 만든다
3. 작업물을 `works/`에 기록하고, 원하면 `sites/`에 맞춤 웹을 만든다
4. 결과가 나오면 기관 페이지 **결과** 칸에 남긴다 — 다음 지원의 재료

### 묻기 — "시니어 기관에 낼 이력 골라줘", "AI 영상 강의 몇 군데서 했어?"
`index.md` → 관련 페이지 → 필요하면 `inbox/` 순으로 읽고 답한다. 근거 페이지를 링크한다. 다시 쓸 만한 답은 `queries/`에 저장.

### 점검 — "위키 점검해줘"
모순, 날짜가 지난 "현재" 항목, 결과·증거가 빈 카드, 연결 안 된 카드, 페이지 없는 기관·역량을 찾아 보고하고 고친다.

## 규칙
- 링크는 상대경로 마크다운 링크 (`[이름](../cards/파일.md)`) — GitHub·Obsidian 둘 다 열림
- 파일 이름은 한글 OK, 띄어쓰기 대신 `-`
- 이 위키가 **이력의 원본**이다. 지원서 data.json·제안서 instructor_profile.md를 고칠 때 여기 기준으로 맞춘다

## 공개 저장소 주의
이 저장소는 **공개(public)** 다. 비공개로 바꾸기 전까지 넣지 않는다:
전화번호, 이메일, 생년, 상세 주소, 강사료·계약 금액, 기관 담당자 개인 정보, 수강생 실명·얼굴 사진.
